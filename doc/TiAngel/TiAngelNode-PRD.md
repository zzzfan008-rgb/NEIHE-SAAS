# TiAngelNode — 独立 3D 视角文本节点 PRD

版本：v0.3（2026-09-21 已确认：侧栏手动添加，不绑定模板）

日期：2026-09-18

交付范围：产品与实施方案，不包含功能实现、依赖安装、真实 AI 调用或部署。
文档路径：`doc/TiAngelNode-PRD.md`。

## 1. 目标与方案结论

在画布左侧“添加节点”中提供独立的 Three.js“3D 视角”节点，不在内置模板预置。用户拖动预览或控件，实时得到环绕、俯仰、画面倾斜的文字描述；文字在第一轮人物场景定版时生效，沿用现有人工确认和第二轮服装精修流程。

核心交付闭环：添加节点 → 用户手动连接第一轮视角输入 → 开启视角控制 → 拖动预览/滑杆 → 点击展开角度文本 → 运行第一轮 → 查看并确认基准 → 第二轮精修。

已确认 V1 定义：控制摄影机相对人物的观察角度以及画面旋转。“倾斜”定义为画面倾斜（camera roll），不隐式解释为身体侧倾、躯干前倾或头部倾斜。若需要后者，应增加独立的姿态需求和参数，不能复用 roll。

TiAngelNode 使用“Three.js 控件 → 结构化角度 → 视角语义 → 模型文本适配器”的分层架构。文本适配覆盖项目当前注册的全部 9 个生图模型；实际运行按下游节点模型选择适配器，模型 ID、适配器版本和最终文字随运行计划冻结。第一轮沿用 local 的四模型准入：Gemini 3 Pro、GPT Image 2、GPT Image 2.5 Flare、Gemini 3.1 Flash Image；后续阶段沿用各自准入，不因文本适配自动开放。

已确认的 3D 控件采用“中心参考图平面＋水平轨道/垂直弧线＋可拖动相机球＋指向中心的方向线”。用户从固定外部视角观察整个控件，不是透过生成用虚拟相机查看人形。参考图始终是二维图片，不重建人物、服装或场景，不模拟图片的真实侧面/背面。输出为可读文本指令，不承诺生成图逐度还原，也不宣称实现了 3D 换装或骨骼控制。

## 3. 范围

### 3.1 V1 包含

1. 一个独立可保存、复制、删除和撤销的 `ti-angle` 节点；显示名“3D 视角”，组件建议名 `TiAngelNode`。
2. Three.js 中心参考图平面、水平轨道、垂直弧线、相机球、方向线，以及明确的前/后/人物左/人物右标识。
3. 环绕角、俯仰角、画面倾斜的拖动与数值输入，常用预设、重置、复制文本。
4. 侧栏创建后无连线、默认关闭；用户手动连接并开启后输出约束。
5. 前后端共用确定性文本编译、第一阶段消费、基准失效和运行快照。
6. WebGL 不可用时仍能通过标准控件编辑参数与输出文本。
7. 保留现有图片输入、人工确认、结果查看、比较、下载、继续处理及跨项目恢复。
8. 支持通过画布侧栏现有“添加”菜单创建 TiAngelNode，不依赖模板。
9. 对当前全部 9 个生图模型提供文本适配器；文本默认折叠且不露出摘要，用户点击后才展开查看。

### 3.2 V1 不包含

- 上传 3D 模型、人物三维重建、真实布料模拟、骨骼关节编辑、动作捕捉。
- 将预览截图、深度图、法线图或骨架图作为新增模型输入。
- 焦距、景别、镜头距离、轨迹动画、批量多角度生成。
- 全站通用姿态系统、其他工作流自动接入、移动端适配。
- 自动付费生成或角度变化后自动重跑。

## 4. 模板与用户流程

```text
人物图、场景图、姿势图、服饰/配饰参考 ─┐
                                     ├→ 第一轮定版 → 人工确认 → 第二轮精修 → 原有后续节点
3D 视角节点 ── angle-direction 文本 ───┘
```

- 内置模板不包含 `ti-angle`、`angle-direction` 或预览默认边。用户手动添加后，可连接 `text → stabilize.angle-direction`，并自行连接图片到 `preview-image`；不复制图片资产。
- 新节点默认 `enabled=false`，无连线且无角度约束，不阻断第一轮运行。界面显示“未启用，沿用参考图视角”。
- 用户开启后拖动相机球调整环绕和俯仰；水平轨道手柄只改环绕，垂直弧线手柄只改俯仰。用独立“画面倾斜”滑杆控制 roll；三项都有度数输入与键盘操作。
- 参数/文字实时预览，松手或数值提交时写入文档。用户仍需点击现有第一轮运行按钮；新节点没有 AI 运行按钮。
- 未连接时可以预览和复制文本，显示“尚未连接第一轮”；不自动写入下游可编辑 prompt，也不创建隐藏关联。
- 删除节点或断开其已生效连接，恢复参考图角度规则，并使受影响的旧基准失效。
- V1 在任意项目画布的侧栏“添加节点”菜单中选择“3D 视角”创建，并支持复制使用。复用现有侧栏添加流程和节点放置规则；手动添加的节点默认关闭、无连线，由用户连接到第一阶段的“3D 视角”输入。创建入口不限项目，但下游连接仍受 V1 范围限制，不自动扩展到其他生成节点。一个第一阶段最多连接一个角度节点，多余连接在前后端明确拒绝。
- 参考图必需性沿用 local 当前模式，兼容 composed-person；本节点不代替人物或服装图片，也不使可选姿势变成必需。

## 5. 交互与布局提案

以下尺寸为待评审提案，以 CSS px 和画布 100% 缩放为基准。

- 节点宽 320px，标题保留在既有 NodeFrame 标题体系内；从上到下为标题/启用开关、约 288×208px 预览、预设、三行参数、文本和复制/重置操作。
- 节点位置遵循现有侧栏添加规则，不移动已有节点，不指定模板坐标，不自动连线。
- 预览明确标注“视角示意，非生成结果”；中心参考图平面固定，带顶部和正面方向标记。相机球沿球面移动，方向线始终指向中心；水平轨道和垂直弧线表达两个角度维度。固定外部观察相机负责绘制整个控件，与输出角度所描述的虚拟相机分开。
- roll 通过相机球旁带“上”方向标记的取景框旋转表达，不旋转中心图片，不把轨道整体倾斜作为 roll。空参考图时显示带方向标记的占位平面，角度控件仍可用。参考图按原比例 contain 显示，不拉伸、不把背面贴图伪装为真实背面。
- 新节点内部滑杆、输入、按钮、开关、提示和错误状态采用项目本地 shadcn；主题由 `data-theme` 与 `--gc-*` 驱动。
- 外部观察相机固定，不开放其 orbit/pan/zoom；目标虚拟相机固定目标点、距离和视场，只调整三轴。滚轮保留画布原行为；手柄和相机球拖动不能同时拖节点或框选画布。预览空白处不修改角度，节点标题/外框仍可拖动。
- 拖动区域使用 React Flow 对应的交互隔离；按 pointer capture 处理松手和移出边界。Escape、pointercancel、失焦或切换页签取消未提交手势并释放控制。
- 数值输入单位“°”；方向键每次 1°，Shift+方向键每次 5°，Home/End 到边界。输入框允许编辑中暂为空，提交时才校验；非法值不保存、不变成 0。
- 输出区域默认仅显示“查看输出文本”入口，不显示输出正文、首行或语义摘要；三行角度数值控件仍常显。点击后展开模型名称与只读全文，再次点击收起。折叠状态是本地 UI 状态，不进入文档历史、会话持久化或业务 Store。
- 展开内容为只读文本，可选中及复制；复制失败保留文本供手动复制，不提示成功。按钮使用 `aria-expanded` 和关联内容 ID，支持 Enter/Space、可见焦点及收起后的焦点恢复。自定义补充要求继续在原换装节点编辑。
- 模型由下游决定，节点不增加业务模型选择器。展开时按接收节点分别显示“节点名称 / 模型名称 / 文本”；同一角度节点连接多个第一阶段时分别编译和复制，不混用一个全局结果。下游切换模型后同步重新编译，不展示旧模型文字作为当前结果，也不自动展开面板。
- 未连接时，展开面板显示“通用视角描述（未绑定模型）”，可复制但不能标称已适配某模型。它仅是语义预览，不作为运行快照；实际连接后由下游模型替换。其余全局模型的适配器纳入单元测试，本期不为它们开放新的工作流连接入口。
- 预设：正面 0°、人物左前方 +45°、人物右前方 -45°、人物左侧 +90°、人物右侧 -90°、背面 -180°。预设同时把俯仰和画面倾斜归零，不改变启用开关；重置把三项归零，也不改变开关。
- 关闭时禁用拖动和参数编辑但保留上次值；重新开启恢复值。关闭状态不能把全 0°误当作“跟随参考图”。
- 不设置额外全屏编辑器或模态弹窗。窄桌面依靠原画布平移和缩放查看；1024/1280/1440 下节点内容不能被自身布局截断，也不能导致页面级水平溢出。
- 可访问名称明确区分三个轴；聚焦可见。文本变化不逐帧播报，提交后温和播报摘要。减少动态效果偏好下禁用插值动画。

## 6. 参数、方向约定与文字规则

### 6.1 参数规范

| 字段 | UI 名称 | 范围/默认值 | 语义 |
| --- | --- | --- | --- |
| `enabled` | 启用视角控制 | false | 为 false 时不向下游输出角度约束 |
| `azimuthDeg` | 环绕角 | [-180,180)，默认 0 | 0 为人物正前方；+90 为人物自身左侧；-90 为人物自身右侧；-180 为正后方 |
| `elevationDeg` | 俯仰角 | [-45,60]，默认 0 | 0 为围绕固定目标点的平视；正数从高处俯拍，负数从低处仰拍 |
| `rollDeg` | 画面倾斜 | [-30,30]，默认 0 | 最终画面内容以观看者视角顺时针为正；0 保持画面竖直 |

持久化精度 1°。交互可临时使用浮点数，提交时四舍五入并将 -0 规范成 0。环绕角以 360°周期规范化（180°与-180°保存为同一值）；俯仰与 roll 的手势到边界停止。服务端拒绝非数值、NaN、Infinity 和超出其规范范围的提交，不能静默修复有歧义的输入。

坐标系约定：Three.js 世界 +Y 向上，参考平面位于 XY 平面、名义人物正面为 +Z，人物自身左侧为 +X。固定中心 T 为目标、r 为固定距离，a/e 为弧度；该约定不从参考图自动估计真实人物朝向，不能把任意输入图当作已标定正面。UI 必须显示“0°表示约定正面，不是自动识别原图拍摄角度”。

```text
virtualCameraPosition = T + r × (sin(a)cos(e), sin(e), cos(a)cos(e))
```

相机球位置使用上述公式，方向线看向 T，再单独旋转其取景框标记表达 roll。外部观察相机不随这些值移动。raycast 命中手柄后将指针映射到对应约束轨道/球面，保持抓取偏移；反解角度时处理 ±180°连续性、遮挡命中和边界夹取。底层旋转正负号必须以带顶部标记的测试场景验证，不能直接拿 Euler.z 的符号当产品定义。

### 6.2 输出规则

- 使用共享纯函数 `encodeTiAngleSemantics(config)` 生成方向语义，`compileTiAngleText(config, targetModelId)` 调用显式模型适配器，不调用 LLM。连续角度数值为真相，离散方向词为派生标签，不把角度吸附成 45°档位。模型适配只改变文本表达，不改变数值、坐标约定和持久化结构。
- enabled=false 输出空字符串；开启时即使三个角为 0，也明确输出正面、平视、画面不倾斜。
- 顺序固定：相机方位 → 俯仰 → 画面倾斜。数字、中文方向和预览保持一致。
- 方位分段：按环绕角到最近的八个 45°方向生成正面/左前/左侧/左后/背面/右后/右侧/右前的标签，以精确度数补充；等距边界固定归入角度递增侧，180°按-180°处理。
- 非零俯仰直接写“从高处俯拍 N°”或“从低处仰拍 N°”；roll 写“画面顺/逆时针倾斜 N°”。避免“人物向左倾斜”等身体动作词。
- 不从预览推断人物性别、身份、情绪、服装款式、灯光、背景或焦距。

### 6.3 生图模型适配

TiAngelNode 不增加 Provider 参数，也不把角度转成额外参考图。适配发生在生成计划编译阶段，使用接收 `angle-direction` 文本的 `scene-stabilize` 节点 `modelId`。UI 可以提前显示预览文字，但服务端入队时必须重新按保存项目和目标模型编译，防止客户端文本过期或被篡改。

适配覆盖运行时 `ImageModelId` 全集，下表为待实现、待效果验证的文本策略，不是已证实的模型最佳提示词。允许不同模型复用同族模板，但每个 ID 必须显式注册并有测试；未知 ID 不静默降级。local 已注册 Gemini 3 Pro，本次补齐其适配器，不增加 Provider 接口。

| 模型 | 全局用途 | 当前“一键换装”是否可用 | TiAngelNode 文字策略 |
| --- | --- | --- | --- |
| `gemini-3-pro-image-preview` | 第一轮场景定版 | 是 | 分段中文，独立声明三轴角度与保持项 |
| `gemini-3.1-flash-image` | 通用生成、多图编辑、虚拟换装 | 是 | 分段的中文自然语言约束；明确写出相机环绕、俯仰、画面 roll，并强调不把镜头变化误解为人物身份或服装变化 |
| `gpt-image-2.5-sunburst` | 通用生成、虚拟换装、局部相关流程 | 第一轮否；保留其他阶段准入 | 较短的指令式文本；每个角度独立成句，使用“最终画面”与“相机视角”措辞，避免只写 Three.js 或 Euler 术语 |
| `gpt-image-2` | 本项目局部修改与虚拟换装 | 是 | 最短的强约束文本；保留整数角度和顺/逆时针方向，明确只改变观察视角，不改变人物、姿势、服装和场景语义 |
| `gpt-image-2.5-flare` | 通用生图及第一轮 | 是 | 注册 GPT 系编辑视角模板，明确方位、俯仰、roll 和保持项 |
| `gpt-image-2-vip` | 通用生成与参考图编辑 | 否，保持原准入限制 | 注册 GPT 系模板，保留独立 ID 和版本，不假设与其他通道效果一致 |
| `flux-2-pro` | 通用生成与参考图融合 | 否，保持原准入限制 | 注册描述式自然语言模板，先描述目标视角，再列主体和外观保持项 |
| `seedream-5-0-260128` | 通用生成与参考图融合 | 否，保持原准入限制 | 注册中文分段模板，区分镜头变化、身体姿势和不变内容 |
| `grok-imagine-image` | 通用生成与参考图编辑 | 否，保持原准入限制 | 注册直接编辑指令模板，三轴分句，明确只调整观察视角 |

适配器必须满足以下共同规则：

- 不改变 `azimuthDeg`、`elevationDeg`、`rollDeg` 的数值和方向；只改变措辞、段落结构和约束强调。
- 当前适配器不输出 Qwen LoRA 专用的 `<sks>` 等触发词，不把角度文本称为原生相机矩阵控制。参考图不可见区域只能由模型推断，不承诺恢复真实细节。
- 不使用模型没有声明支持的 `modelOptions` 字段；TiAngelNode 文本不能伪装成 `aspectRatio`、`imageSize`、`quality` 或 Provider 私有参数。
- 文本始终使用“相机/最终画面”语义，明确禁止从相机 roll 推断身体侧倾；身体姿态仍由现有姿势参考图负责。
- 适配器输出经过长度上限和危险角色覆写检查，不能重新定义参考图编号、人物身份、场景来源、服装来源或优先级。
- 适配版本与模型 ID进入运行快照。修改适配规则后，旧运行继续显示旧文本，新运行使用新版本；不回写历史记录。
- 由于模型对大角度和背面视角的遵循程度不能由 API 契约保证，真实效果需按模型分别验收；通过文本适配测试不等于生成效果达到逐度精度。

示例：

```text
enabled=true, azimuthDeg=45, elevationDeg=15, rollDeg=-10
→ 从人物自身左前方观察，相机环绕角为相对人物正面向其左侧45°；
  从高处俯拍15°；画面逆时针倾斜10°。

enabled=true, azimuthDeg=-180, elevationDeg=0, rollDeg=0
→ 从人物背面观察，相机环绕角为180°；平视；画面保持竖直、不倾斜。

enabled=false
→ 下游输出空字符串；UI 显示“未启用，沿用参考图视角”。
```

## 7. 接口、持久化与执行计划

### 7.1 节点契约提案

```typescript
interface TiAngleConfig {
  version: 1;
  enabled: boolean;
  azimuthDeg: number;
  elevationDeg: number;
  rollDeg: number;
}

interface TiAngleCompiledText {
  adapterVersion: 1;
  targetModelId: ImageModelId; // 使用项目已有全局 8 模型类型，而非换装子集
  text: string;
}

// 运行态节点按现有 NodeData 基类补充 status/error；二者不进入文档快照。
interface TiAngleDocumentData {
  kind: "ti-angle";
  label: string;
  angle: TiAngleConfig;
}
```

节点增加可选显示输入 `id="preview-image", valueKind="image", maxSources=1`，仅允许现有图片类来源（图片输入节点或人物板输出）连接；单输出 `id="text", valueKind="text"`。新增第一阶段可选输入 `id="angle-direction", valueKind="text", maxSources=1`；角色标签“3D 视角”。V1 只允许 `ti-angle` 接该角色，不接受任意自由文本节点；不开放到 standard 换装、第二阶段、图片输入或 Results。

参考图来源以显式边为准，不从下游反向猜测，也不在节点新增上传/资产副本。图片输入或人物板有多张输出时使用其既有排序中的第一张；没有可用图片时显示占位平面。仅通过已鉴权的项目图片访问路径加载，沿用资源权限与格式限制；不接受任意远程 URL。纹理、加载状态、解码结果为本地运行态，不进入项目快照。图片替换或断线只更新示意，不改变角度文本或单独使下游基准失效；若同一来源也是下游人物图，其原有业务边仍按既有规则使基准失效。

结构化角度是唯一文档真相，生成文字为派生值，不另存可编辑 text，防止参数与文字不同步。运行快照保存规范化参数、来源节点 ID、编译版本和实际编译文字，供历史追溯与重试使用。

### 7.2 编译与执行

1. 前端用已提交参数展示文字；运行前结束/取消尚未完成的角度编辑，再沿用现有保存后运行流程。
2. 服务端在现有已保存项目与提交计划一致性校验中，从 angle-direction 边解析来源节点；校验类型、数量和参数，重新编译文本。
3. 将开启的约束写入 `stabilize` 的计划参数 `angleControl`，包含 `sourceNodeId`、`config`、`adapterVersion:1`、`targetModelId`、`text`；不追加到可编辑的 `data.prompt`。未开启则省略 angleControl。`targetModelId` 必须来自本次实际执行的换装节点。
4. 该文本边参与拓扑/环校验，但不进入图片 `upstream` 列表，不产生图片占位，不计入图片数量，也不改变既有 referenceRoles/图序。调整所有目前按总入边数计图片名额的相关判断。
   `preview-image` 边保存于文档并参与类型/环校验，但只是 UI 显示依赖；计划编译不能沿它向下游传播图片、建立生成依赖或要求图片先生成。显示图片缺失不阻断文本编译与运行，且不得重复传递模板已有的人物图。
5. 单独运行 stabilize 时，即使角度来源不在执行子图，也从保存的来源节点编译参数，并按 stabilize 当前模型重新适配，不依赖“先运行角度节点”。
6. 若整图计划包含 ti-angle 步骤，作为本地纯数据步骤处理，返回空 images、providerRequests=0，不产生生成结果卡、计费项或 AI 请求；不能当作生成目标单独提交。
7. Worker 仅消费已入队的 angleControl 快照，重试或服务重启不能重新读取当前画布角度。处理未知编译版本时明确报错，不按新规则悄悄重写旧任务。
8. 如果 stabilize 模型不在当前换装允许清单，服务端返回明确的模型不支持错误；不能回退成通用生图模型文字或静默使用旧模型文字。身份、鉴权、文件访问、幂等 clientRequestId 和队列并发保护均沿用现有流程。本功能无需新增 API 路由或独立数据库表。

### 7.3 持久化兼容

- 扩展 NodeKind、WorkflowNodeData、NODE_SPECS、DocumentNodeData 和快照字段白名单；同步客户端会话恢复、服务端 schema、模板读取与节点注册。
- 当前版本 17 只是调研基线；实施时使用下一个可用版本。旧项目不自动插入节点、不改变连接、不开启新行为；新类型不能伪装成旧 schema 数据供旧客户端读取。
- 覆盖保存/重开、刷新草稿、复制粘贴、模板克隆、撤销重做；缺失可选新字段按明确的版本迁移处理，非法值拒绝。
- 禁止序列化 Scene、Camera、Quaternion、renderer、DOM、临时拖动值和 WebGL 状态。
- 托管一键换装模板若残留预置 TiAngle 则刷新为无绑定版本；不批量改写用户已有项目、自建模板或运行时输出，保留其手工配置。

## 8. 第一阶段提示词优先级

当前模板已经固定场景和姿势来源，不能只把角度文本放进“补充要求”。启用且连接时按以下维度组装一致规则：

| 维度 | 生效来源 |
| --- | --- |
| 人物身份、脸型、肤色、体型 | 原身份图及身份锚点 |
| 服装版型、纹理、配饰 | 原服装与对应参考图 |
| 相机环绕、俯仰、画面 roll | angleControl 的明确参数 |
| 场景内容、材质与光照风格 | 原场景图；允许为目标镜头合理重建透视 |
| 肢体动作及关节相对关系 | 原姿势参考；按新相机角度合理投影 |
| 第二阶段镜头、姿势和构图 | 用户确认的第一轮基准图 |

- 未启用或未连接时保留原提示词分支及原有优先级，避免改变老项目结果。
- 启用时，场景分析和姿势分析的解释须限定在上表范围。不能一边要求固定原场景镜头/二维骨架投影，一边要求换视角。
- 继续传递既有姿势引导和图序，但声明保留相对肢体关系而非逐像素复制投影。文本控制对大角度、背面和遮挡的可靠性须通过人工效果验收；如果不足，后续可另立 3D 引导图方案，不在本期悄悄增加模型输入。
- 角度约束由服务端作为独立受控段落拼装；执行沿用 local 当前策略，第一轮不调用通用提示词增强，也不在内容拒绝后触发 safetyFallback。
- 启用角度不增加 Provider 请求次数；第二轮仍沿用自己的增强及回退规则，不重新应用三轴角度。
- 模型适配文本在计划编译时生成并冻结，不交给提示词增强改写；在增强成功或失败回退后，由服务端拼入相同受控段落，不能删除、翻译成相反方向或重新解释角度，不回退到跨模型通用文本。
- 同步检查候选图评选逻辑：开启时不能因偏离场景原镜头而惩罚正确的新视角；仍必须检查身份和服装。模型评选不作为精确角度测量。
- 用户自填补充文字与本节点角度矛盾时，受控角度字段优先；界面提示“启用后，镜头角度以本节点为准”。身份/服装保护规则仍不可被角度文字覆盖。

## 9. 历史、基准确认与竞态

- 一次拖动松手只形成一次文档历史操作；局部实时预览不逐帧写 Store 或自动保存。无实际参数变化不记历史。
- 提交携带捕获的 `tabId + projectId + documentEpoch + nodeId`；页签切换、项目替换或节点删除后迟到事件丢弃。只读项目只可查看和复制文字。
- 在同一次文档变更中更新角度与受影响 stabilize 的 basisRevision，保证撤销/重做可还原一致状态。enabled 的切换、有效参数修改及有效连接增删均参与判断；节点移动、复制文字及 renderer 重建不影响基准。
- 关闭节点的未生效参数不使基准失效；重新开启时按有效约束重新计算。连接禁用节点不改变有效约束；删除启用且已连接节点则会改变。
- 约束变化后，保留旧图片和 Results，但清晰提示“视角已变更，请重新生成并确认第一轮”；旧基准不能直接重新点击确认来冒充新角度结果。
- 第一轮提交时记录对应的 basisRevision 和规范化约束指纹。结果只有与当前基准输入一致才可确认；生成期间改角度，旧结果仍正常归档，但不自动成为当前可确认基准。
- 服务端第二轮入队须校验确认引用与已完成第一轮运行的版本/指纹对应关系，不能只信客户端的 approvedBasisRevision；先核实既有记录能力，缺失时补充现有运行元数据链路。
- 已经入队的第二轮按其冻结基准继续执行；新角度只影响后续任务，不能篡改历史或清空正在运行任务的产出。
- 撤销返回原始配置时是否可复用旧基准，由完整输入指纹匹配决定，不仅比较角度；身份图、场景图、姿势图或服装的变化不能被绕过。

## 10. Three.js 实施建议与降级

- 新增 three 依赖并按实际版本配套类型；实施时锁定版本和 lockfile，不在 PRD 中猜测最新版本。
- 使用原生 Three.js 的局部 React 封装、固定外部观察相机和 raycast 手柄交互；本期不以 OrbitControls 驱动用户输出角度，避免混淆观察相机与目标相机。无需第二套状态系统或全局 3D 框架。
- 图片平面、轨道、球与方向标记使用本地基础几何；纹理复用可选参考图。图片加载失败时保留占位与控件，不依赖外部模型 CDN。异步纹理加载绑定文档身份及来源版本，过期回调丢弃并释放纹理。
- 按节点可见性懒加载 Three.js，3D 代码不进入首屏主包；只对正在编辑的一个节点保留交互 renderer，其他节点使用当前参数生成的静态控件预览；不能以性能降级为由展开或露出文本摘要。
- 固定距离、target 和 FOV，DPR 上限建议 1.5；按变化渲染，无操作时停止 requestAnimationFrame。页签切换、节点删除、组件卸载时释放事件、controls、几何、材质和 renderer。
- WebGL 初始化失败/上下文丢失时，显示“3D 预览暂不可用，可继续用角度控件设置”，保持现有参数和文本；不重置文档。可手动重试预览。
- 纯文本编译与 Node 测试不导入 Three.js 或访问 DOM；SSR/服务端校验与 WebGL 完全分离。

### 12.2 真实生成效果验收（另行授权）

自动化只能证明控件和最终请求文本正确，不能证明 AI 对几何指令的遵循程度。授权真实调用后，以固定人物/场景/姿势/服装参考，比较关闭、正面、左右45°、侧面、背面、俯拍、仰拍与正负 roll 的效果；记录模型、角度、输入、最终提示词、调用量和结果。

人工判断方向是否明显正确、人物身份/服装是否保持、姿势是否合理。V1 不设无法从单张图片可靠测量的逐度误差承诺。若大角度持续不符合预期，应报告适用范围和改进选项，由用户决定是否缩小发布范围或增加图像引导，不能以文本测试通过替代效果验收。
