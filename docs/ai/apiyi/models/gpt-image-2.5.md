# GPT-Image 2.5 integration (2026-09-10)

Sources read before implementation: [overview](https://docs.apiyi.com/api-capabilities/gpt-image-2/overview.md), [text generation](https://docs.apiyi.com/api-capabilities/gpt-image-2/text-to-image.md), [image editing](https://docs.apiyi.com/api-capabilities/gpt-image-2/image-edit.md). These are APIYi gateway claims, not an independent OpenAI model-availability statement.

- New general generation nodes default to the 2.5 family. Requests without references use Flare; requests with references use Sunburst, irrespective of which 2.5 family label is selected. **First-round scene stabilization is the exception:** an explicit Flare selection uses Flare's multi-image edit endpoint and does not switch to Sunburst. Legacy VIP is retained, not silently converted to a differently priced model.
- `APIYI_BASE_URL=https://api.apiyi.com/v1`, `APIYI_API_KEY` stay server-side. `APIYI_GPT_IMAGE_GENERATION_MODEL` / `APIYI_GPT_IMAGE_EDIT_MODEL` override upstream names; defaults are `gpt-image-2.5-flare-2026-09-08` / `gpt-image-2.5-sunburst-2026-09-08`. The existing provider path builder normalizes the trailing `/v1` before appending endpoint paths.
- Quality is always sent: low / medium / high / xhigh / max; new tasks default medium. Legacy ordinary GPT Image 2 projects map low → low, medium → high, high → max during document loading on both client and server, including old schema versions. First-round scene stabilization retains the selected GPT Image 2 model and its original low / medium / high quality instead of applying that migration. Old records/results remain available. Missing old quality is treated as medium. A configured ordinary GPT Image 2 fallback rejects xhigh/max before networking.

- Upstream requests are synchronous, with no upstream task ID. The application's own durable run queue is separate and still supports recovery. Timeout floors are 360 seconds for low/medium and 600 seconds for high/xhigh/max; nginx response/send timeouts are 660 seconds. The browser submits a queued run and subscribes to its status instead of owning the upstream image socket. Ambiguous 2.5 failures terminate as outcome_unknown without automatic paid replay; explicit retryable rejections retain the existing bounded policy. No Serverless execution layer is configured in this repository. Deployment must keep any additional gateway above these limits.
- Generation sends JSON, edits multipart with ordered `image[]`, at most 16 references. Both send quality, n=1 and output_format=png; neither sends response_format or input_fidelity. Base64 output is decoded by the existing image validator and persisted through the existing result pipeline, retaining view, download and set-as-input behavior.
- References above 1.5 MiB are resized inside 2048×2048 without enlargement. JPEG/WebP use quality 90, PNG stays lossless in PNG format. Aggregate >6 MiB is reduced further. Compression failure preserves the original and logs only its index; if fallback leaves the aggregate above 6 MiB, warn and continue as explicitly approved. Invalid/unsafe image inputs still fail validation.
- Masks retain the existing region-guide and local-compositing pipeline. This migration does not change the product's mask semantics.
- Returned usage and the optional request ID are written to the server's `[gpt-image-2.5] completed` log and returned by the provider adapter. They are not persisted in generation history or the usage database/UI. The token-cost **estimate** uses uncached rates of $5/M text input, $8/M image input and $30/M image output; it is not evidence of actual account debit, and cache discounts or channel charges may differ.

## First-round scene stabilization (2026-09-17)

- New template default: `gemini-3-pro-image-preview`. Existing Flash nodes retain their model and titles. The shared node/Inspector editor offers Pro, GPT Image 2, Flare and legacy Flash, plus optional creative ideas.
- Gemini output tiers: 1K / 2K / 4K. GPT tiers: 2K / 4K, translated to aligned pixel dimensions from the chosen aspect ratio. Aspect ratio follows the scene by default; explicit choices are 1:1, 4:5, 3:4, 2:3, 9:16 and 16:9. These are the existing garment-workflow ratios, not the full upstream ratio list.
- For this stage only, explicit model identity takes priority over `APIYI_GPT_IMAGE_EDIT_MODEL`. Other stages/nodes retain the environment-based routing above. First-round GPT Image 2 quality defaults to medium; Flare additionally exposes xhigh/max. Switching to a model that does not support the selected quality resets it to medium; switching from Gemini 1K to GPT changes the tier to 2K.
- `server/engine/runner.ts` retains shared identity, garment, pose, scene and accessory role constraints. Pro adds scene perspective/contact-shadow instructions; GPT Image 2 emphasizes full-scene multi-reference editing rather than editing the face crop; Flare uses a shorter task introduction and explicit output constraints. Creative ideas are a separate section subordinate to reference roles. These are application prompt strategies, not verified guarantees of model quality.
- APIYi's [image-edit contract](https://docs.apiyi.com/api-capabilities/gpt-image-2/image-edit.md) lists Flare as an editing model. Its [Nano Banana image-edit contract](https://docs.apiyi.com/api-capabilities/nano-banana-image/image-edit.md) supplies the exact Pro preview endpoint used here. No independent OpenAI model-availability claim is made.
- Regression coverage: `tests/scene-stabilize-models.test.ts`, `tests/dag.test.ts`, and the first-round desktop controls test in `e2e/workbench.spec.ts`. All provider requests are mocked; actual paid output quality is not validated by these tests.

## Verification

`tests/gpt-image25.test.ts` uses a mocked gateway; normal tests never call paid providers. `scripts/verify-gpt-image25-live.ts --execute-paid-tests` is an explicit, separate paid acceptance command and creates an exclusive marker to prevent accidental duplicate billing. Outputs live under ignored `data/acceptance/`. Never delete its marker to retry an ambiguous request without approval and billing reconciliation.

2026-09-10 live acceptance: one 1024×1024 medium generation (33.352s, 52 text input / 0 image input / 439 output tokens, estimated $0.01343), followed by one edit using its output (128.026s, 59 text input / 1024 image input / 439 output tokens, estimated $0.021657). Both returned valid PNG images. Actual debit is unverified. Generation request ID: `req_6df7833938694b0397b7e34defb14b67`; edit response did not provide `x-request-id`. Images were visually inspected: ivory shirt, then green shirt with the general composition preserved; not pixel-identical editing.
