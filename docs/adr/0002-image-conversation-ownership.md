# 图片对话以起始图片归属，多图融合不合并历史

用户于 2026-09-21 确认不同图片各自拥有对话历史，选择按起始图片组织，而非在项目内共用一条对话。为了让多图融合后的编辑过程保持连续，从 A 的对话加入 B 融合得到 C 时，本轮融合及对 C 的后续修改继续归属 A 的对话；B 的历史不被合并或改写。

对话起始图与本轮底图区别对待：底图可以随迭代变化，对话归属保持稳定，参考图排序也不改变该归属。

用户进一步确认：将结果 C 加入画布后，再从 C 进入对话修改，应回到生成 C 的原对话并以 C 为本轮底图。结果加入画布需保持其对话来源关系，不能因新增节点而割断历史。

同一项目内复制图片节点也保留来源关系，副本与原图共享原对话，避免因画布节点复制而割裂修改过程。副本重新上传替换为另一张图片后建立独立对话，原对话及历史保留，防止无关图片继承旧要求。

跨项目复制则只带图片，在目标项目建立独立对话，不继承原历史或有效要求；原项目不受影响。此边界优先保障项目间修改过程独立，不因相同图片来源而共享跨项目对话。
