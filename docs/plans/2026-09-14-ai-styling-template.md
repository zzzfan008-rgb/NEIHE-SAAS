# AI 搭配内置模板实施方案

状态：需求及方案已确认，功能已实施于独立分支 `codex/ai-styling-template`。验证记录见 `2026-09-14-ai-styling-verification.md`；未提交、合并或部署。

## 1. 已确认的产品行为

- 新增“AI 搭配”内置模板，参考“一键换装”的入口与节点视觉，固定三个节点：上传参考图 → AI 搭配 → 搭配结果。
- 上传节点支持同一件服饰的多角度图片。第一张默认主图，可点击“设为主图”；主图决定核心服饰、人物和背景，细节图只补充服饰结构、材质、图案及背面。
- 用户点击“识别服饰”后才调用识别服务。识别结果可纠正；同时出现上下装时，用户选择保留上装、下装或整套服装。
- 保留上装时补齐下装，保留下装时补齐上装，支持连衣裙、连体裤及整套服装的造型搭配。尽量保留核心服饰原款、颜色、图案和细节。
- 外套、鞋履、包袋、配饰、帽子使用五个独立按钮开关，默认关闭。关闭表示不新增，原图已有单品保留；开启允许选择或替换同类单品。
- 核心服饰保护优先：保留整套服装时，原有外套也不可替换；外套本身是被选中的核心上装时同样不可替换。
- 提供补充要求输入框。补充要求可细化搭配和指定场景，但不能绕过关闭的单品开关或核心服饰保护；提示用户需要新增该类单品时先开启按钮。
- 人物参考图尽量保留原人物与背景；单件服饰图生成合适模特及简洁浅色棚拍背景。生成全身图；主图缺失的身体或背景部分允许合理补全，不臆称能还原不可见细节。
- 默认 1 套，可选 2、4 套。多套优先保持同一人物、同一背景、同一核心服饰，只变化搭配单品，接受串行生成带来的等待。
- 连体服饰或保留整套时，若没有可执行的搭配开关且补充要求为空，禁止生成并显示说明。受服饰保护约束而无效的外套开关不计作可执行操作。
- 沿用现有图片模型、尺寸和质量控件。无需新增独立人物、季节、风格或背景选择器。

## 2. 具体布局与状态

模板初始三节点水平排列：上传节点宽 280px，搭配节点宽 320px，结果节点沿用现有尺寸；相邻节点水平净间隔 80px，顶部对齐。创建后沿用模板 fitView。节点标题始终可见，整体主题、圆角、端口和焦点风格沿用项目规范。

上传节点从上到下：主图预览、细节图缩略图列表、本地上传按钮。缩略图提供“设为主图”和“移除”；选中文件的顺序决定初始排列，异步上传完成顺序不改变主图。复用现有素材上传与标准化接口，已上传图片继续保存为用户素材。

搭配节点从上到下：

1. “识别服饰”按钮及状态提示；识别成功展示简短服饰描述和类别。
2. “保留对象”选择：上装、下装、连体服饰、整套服装。整套穿搭首次识别后不擅自替用户决定保留哪一半。
3. 五个带图标的独立切换按钮，按两列布局自动换行；使用本地 shadcn Button 和 aria-pressed，不能只用颜色区分状态。
4. 三行“补充要求（可选）”输入框。
5. 生成数量 1 / 2 / 4 和现有模型、尺寸、质量控件；模型默认使用项目默认生成模型，初始画幅使用现有 3:4 参数转换规则。
6. “生成搭配”按钮及“正在生成第 X / N 套”进度。

识别状态为未识别、识别中、已识别、需选择、失败。识别失败可重试，不自动生成。无法识别服饰或存在多件同类候选时提示用户更换或裁剪主图，不任意锁定某一件。自动识别出错但有有效服饰描述时可手动纠正类别。

更换、增删参考图、改变主图或输入连线后，旧识别结果失效；重新识别前不能生成。识别响应绑定文档目标和参考图指纹，迟到响应不得覆盖新图结果。调整开关、数量、模型或补充要求不触发重新识别。

搭配结果复用当前 ResultNode 的查看、对比、下载、备注和继续处理能力，显示当前批次成功方案及失败/未知提示。重复生成更新固定结果节点，不自动增加第 4 个节点；旧批次保留在跨项目 Results。仅新批次有成功输出时替换展示，失败不清空旧图片。历史批次的迟到事件不得覆盖较新批次。

## 3. 接入与数据边界

### 模板和节点

- 新增模板 ID `builtin-tool-ai-styling`，在内置模板列表和“一键换装”同组入口中加入“AI 搭配”。保留原一键换装模板。
- 新增专用 `outfit-reference` 和 `ai-styling` 节点，结果复用 `result`；普通单图上传节点行为不变。专用上传节点避免所有旧上传节点承担多图语义。
- 增补 NodeKind、节点注册、默认值、端口、属性面板、输入提取、模板焦点定位、文档快照白名单、项目会话恢复及工作流校验。工作流版本在实施时基于当前版本递增，不改写历史节点含义。
- 持久文档字段包含有序图片引用、主图引用、用户保留对象、五个开关、补充要求、数量、模型参数和固定结果节点关联。模板克隆清空图片、识别信息、运行和输出，不能携带旧账号数据。
- 识别等待、错误和请求令牌属于运行态；服务端识别记录由 ID 和图片指纹引用，客户端不能提交伪造的识别描述作为可信结果。
- 所有异步操作继续绑定 `tabId + projectId + documentEpoch`；生成提交仍使用点击时快照及现有保存/执行一致性校验。

### 服饰识别

- 新增受认证和强制改密保护的 `POST /api/outfit-analysis`。输入为项目 ID、搭配节点 ID、有序本地图片引用、主图引用及 clientRequestId；服务端验证项目所有权、节点/引用一致性和素材访问权。
- 识别时先保存当前项目，服务端只接受已保存的同一组参考图。返回 analysisId、referenceFingerprint、类别候选、服饰描述、是否含人物及已有五类单品信息。
- 复用既有 API易视觉请求机制和已配置视觉模型，建立独立的服饰识别提示词与严格响应校验，不修改禁止提取服饰的场景分析器。
- 使用独立 PostgreSQL 识别记录保存输入指纹、归属、处理状态及结构化结果；同用户相同参考图与识别契约版本复用已成功结果，并以请求号防重复点击。同请求失败后允许显式重试，未知响应先查询状态；网络调用不持有数据库事务锁。
- 新增只读识别状态查询接口，便于页面刷新或请求响应中断后恢复。识别调用受 AI 限流保护，记录请求数量但不伪装成成功图片生成消耗。
- 生成时服务端复核识别记录所属用户、项目、节点和当前输入指纹；失效或不匹配时拒绝入队并提示重新识别。

### 生成与多套一致性

- 继续使用 `/api/run-plan`、持久队列、文件落盘和现有 Provider 接口；新增 AI 搭配分支，以已确认保留对象、服饰描述、开关和补充要求生成约束提示词。
- 用户图主图在前、细节图在后；多套后续请求额外引用首套已落盘结果，明确其仅控制人物、背景、构图，不得覆盖原始服饰参考。第 3、4 套始终参考第 1 套，避免逐轮漂移。
- 图片上限为 `min(产品上限8, 当前模型参考图上限 - 多套时预留1)`。例如多套 Grok 最多上传 3 张，8 图上限模型最多上传 7 张。更换模型或数量导致超限时阻止生成并提示处理，不删除或截断参考图。
- 在 PostgreSQL 为一批搭配保存逐套检查点：方案序号、尝试状态、首套引用、成功文件、请求计数和错误。该状态仅用于搭配运行，不进入画布文档。
- 每套单独执行和提交成功结果；后续失败只处理当前未完成方案，禁止重跑已成功方案。沿用 Worker 租约和取消机制；上游请求已发出但结果不明时保留 outcome_unknown，不能静默重发整批。
- 首套未成功时不生成后续方案。后续发生明确失败时保留已成功方案并报告未完成数量；未知结果暂停后续付费请求。记录与结果 API 能展示部分成功，不被终态错误清理掉。
- SSE 增补搭配进度/部分结果语义，前端按 runId 和方案序号去重；只有批次结束才触发终态。固定结果节点与历史恢复均使用同一套回写逻辑。
- 固定结果节点被用户主动删除时不再自动创建；结果仍可在 Results 查看和恢复使用。不会为维持三节点限制删除用户手动添加的其他节点。

## 4. 影响范围与实施顺序

当前工作树基线为 `14be0b4`，已有色库、品牌色、数据库及部署改动，属于其他工作。实施须保留这些内容；新数据库迁移使用当前末尾之后的版本，不覆盖现有迁移或测试注册。

CodeGraph 已于本轮初始化：320 文件、5,097 节点、19,384 关系。影响分析发现：

- NodeKind 的两层关联涉及 116 个节点，包含快照、会话、端口、画布、服务端执行与校验。
- ensureGeneratedResultNode 关联 updateTabFromRunEvent、runNode、resumeRecentResults、applyRunEventToTab 和撤销历史测试。
- buildExecutionPlan 关联 runPlan 路由、DAG、权限及色板测试。
- 队列 Worker 图结果未列出全部运行测试；以源码和 run-queue 回归补充，不能视为低风险。

实施按四步完成：① 类型/规则与测试；② 识别接口与逐套持久生成；③ 三节点 UI 和模板接入；④ 恢复、权限、桌面验收。每步均基于当前索引重新核对所改符号影响。

## 5. 验证与交付

- 规则测试：上装、下装、连体、整套；多图主次；手动纠正；所有开关关闭/开启；外套保护；补充要求冲突；无有效操作拦截；参考图数量上限。
- 接口测试：身份与素材权限、非法引用、识别去重/失败/刷新恢复、伪造或过期识别记录、旧项目兼容、模板副本清理。
- 队列测试：1/2/4 套串行；首套被正确复用；逐套落盘；已成功不重跑；部分失败、未知、取消、Worker 重启和 SSE 重连；历史及消耗计数正确。
- 文档测试：切换/复用页签、更换主图、迟到上传/识别/生成响应、撤销重做、保存恢复；重复运行保持原三节点且旧结果仍可访问。
- 桌面 E2E：1024、1280、1440 三宽度下检查实际几何、五按钮键盘操作、主图切换、输入隔离、完整识别到搭配结果流程及查看/比较/下载。
- 运行定向测试、npm run check、npm run build、git diff --check；同步 CodeGraph，检查完整差异并运行 affected 选择回归，包含新增源文件。
- gate:codex 当前仍调用 GitNexus，按项目要求不运行，不声称完整门禁通过。
- 所有自动化使用模拟视觉与生图响应。真实服饰保真、同一人物和背景的一致性须另行获得真实 AI 调用授权后用样例验收，不能以模拟测试通过替代效果结论。
- 不提交、推送、合并或部署；这些操作遵守项目现有授权规则。
