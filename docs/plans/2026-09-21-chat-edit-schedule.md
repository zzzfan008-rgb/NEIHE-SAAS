## 1. 估算口径

- 基线：1 名熟悉项目的全栈工程师，1 人日约 6 小时有效开发/测试/修复/文档时间；每周 5 个工作日。
- 各工作包已含自身测试和常规修复，P8 为跨模块回归与交付审查，不重复计算单元测试。
- 假设已接入图片模型可按现有契约调用，PostgreSQL/Docker 测试环境可用，需求无新增；真实模型效果未验证。
- PRD 41 项确定规则不重新逐条审批。P0 的架构、UI 尺寸、无节点旧对话入口等实质选择需集中确认。
- 不含等待用户确认、外部账号/供应商开通、正式生产部署和无限轮模型效果调优。
- 这不是“AI 自动开发速度”保证，不以代码生成速度代替联调/安全验证周期。

## 4. 双人并行备选（尚未授权新增人员/任务）

若有前后端各一人，P0/P1 统一契约后，后端推进 P2→P3→P4，前端用同一契约 mock 推进 P5→P6；P7/P8 联合验收。
关键路径基础约 19–27 个工作日；并行收益受 P3 解析和队列联调约束，不等于人天减半。
加缓冲约 23–33 个工作日（约 5–7 周）；总工程投入仍至少基线 24–34 人日，另预留契约协作约 2–3 人日，缓冲按实际排期复算。
这是资源方案，不自动创建任务、派发代理或更改当前开发方式。

## 5. 风险、预警与重估点

| 风险 | 影响 | 处理与预警 |
| --- | --- | --- |
| 自然语言解析能力不现成 | 多方案数量、中文意图和继承误判 | P0 选择路径，P3 mock fixture 全覆盖；需要新服务/额外成本则先确认再重估 |
| 对话来源不等于 nodeId | 副本误串历史，跨项目泄漏 | P1/P2 身份矩阵先通过；无节点旧对话恢复入口未定则 M0 不关闭 |
| 既有输出完成逻辑覆盖 run 输出 | 重试可能丢失成功结果或重复记账 | P4 使用独立尝试关联，回归全局结果；重大改造超估算须报告 |
| 澄清/未知结果状态不明确 | 重复收费、永久锁死或错误解锁 | P0 定义状态机，P4 测重启/核对/锁释放，禁止盲重放 |
| UI 在 1024px 下拥挤 | 输入区不可用、画布被遮挡 | P0 验稿，P5 实测几何，不凭截图观感判通过 |
| 工作区已有变更 | 基线漂移、无关回归 | 开发前批准基线与文件清单，发现重叠停止覆盖并对齐 |
| 本地 gate 仍依赖 GitNexus | 无法声称完整 gate 通过 | 禁用该脚本，记录缺失；迁移需另行授权，不偷塞本功能 |
| 真实网关效果偏差 | mock 通过但效果未达标 | 单独取得付费验收授权；记录图片质量/时延/费用，不算已验证 |

P0、P4、P7 结束时重估剩余工作；单包超上限 1 个工作日或预计总量增长 >20% 时报告原因、影响与备选方案。
不得以赶周期为由删减 A01–A65、权限校验、三档验收或未知结果保护。

## 6. 发布不包含在基础周期

本地交付不等于上线。发布批次需另外确认提交/推送、合并、镜像构建与部署权限。
计划交付迁移说明、备份/回退步骤和在途任务兼容性说明；未经授权不改生产数据库、不重建当前 Docker 服务。
真实生成验收和生产发布用时在获得权限及环境信息后补充，不虚构固定 localhost 端口或生产状态。
