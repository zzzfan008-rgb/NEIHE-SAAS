# 侧栏对话修改桌面 UI 验收稿

状态：P0 已确认。此稿只定义桌面端侧栏的几何、交互和可访问性，不改变对话领域数据契约。

## 1. 右侧占位布局

`WorkbenchShell` 继续单次挂载画布、React Flow provider 和上下文树。属性与对话共用同一个右侧 dock，dock 展开时通过 flex 占位收窄画布，不覆盖画布内容；不调用 `fitView`，不修改 React Flow viewport，不清空选择。

右侧 dock 宽度按窗口宽度固定验收：

| 窗口宽度 | dock 宽度 | 画布约束 |
| ---: | ---: | --- |
| 1024 CSS px | 360 px | 剩余区域必须可见且不横向溢出 |
| 1280 CSS px | 400 px | 历史和输入区完整可操作 |
| 1440 CSS px | 440 px | 历史、参数和结果卡片不挤压 |

属性和对话使用同一宽度，避免切换面板时画布发生二次跳动。右侧入口固定在画布右上角，属性按钮在上、对话修改按钮在下；入口不占用画布文档空间。

```text
┌──────────────────────────────────────────────┬──────────────┐
│                                              │ 属性 / 对话  │
│              React Flow 画布                 ├──────────────┤
│        保持现有缩放、平移和节点选择          │ 面板标题      │
│                                              ├──────────────┤
│                                              │ 模式 Tabs     │
│                                              ├──────────────┤
│                                              │ 历史滚动区    │
│                                              │ 轮次/结果卡片 │
│                                              ├──────────────┤
│                                              │ 固定输入区    │
└──────────────────────────────────────────────┴──────────────┘
```

## 2. 面板状态

状态为 `closed | properties | conversation`，只存在于 `WorkbenchShell` 本地 reducer：

- 点击属性：打开或收起属性；
- 点击对话修改：打开或收起当前对话；若当前所指图片属于另一对话，则切换到该对话而不是误收起；
- 两个面板互斥，但切换不卸载画布；
- 收起不清空文本、图片、蒙版、历史或运行任务；
- Escape 先关闭蒙版/图片弹层，再关闭对话面板；焦点返回触发按钮；
- 结果/记录 flyout 仍沿现有独立行为，不进入属性/对话互斥状态。

按钮使用项目本地 shadcn `Button` + `Tooltip`，必须有 `aria-label`、`aria-controls`、`aria-expanded` 和可见 focus ring。

## 3. 对话面板结构

从上到下固定为：

1. 标题栏：`对话修改`、当前来源简述、关闭按钮；
2. 模式 Tabs：`单图修改`、`多图融合`、`局部重绘`；
3. 历史区：`min-h-0 flex-1 overflow-y-auto`，按轮次顺序显示原始指令、输入快照、状态、结果和操作；
4. 底部 composer：本轮底图/有序参考图、蒙版入口（仅局部重绘）、可折叠参数区、指令输入和发送按钮。

历史卡片不能变成会话列表。每张结果单独提供查看、对比、下载、继续修改、加入画布；未知结果必须显示“结果待确认”，不能使用成功或普通失败样式伪装。

## 4. 空态和选择态

- 没有选择图片但项目已有当前对话：打开后恢复当前对话，不清空本页草稿；
- 没有选择图片且没有当前对话：展示本地上传、素材库入口；选图完成前发送按钮禁用；
- 多选图片后打开对话：先展示具体图片选择器，不默认第一张、不自动融合、不自动生成；取消不改变当前对话或草稿；
- 画布普通点击或拖动图片只改变画布选择，不切换对话；只有明确点击对话修改才定位新来源。

## 5. 三种模式

### 单图修改

输入区恰好一张底图；空图片或空白指令显示具体错误并禁止发送。

### 多图融合

输入区显示图 1–图 8，可拖动排序和移除；图号、历史快照、服务器请求和上游参考顺序必须一致。图 1 决定对话归属和默认比例。

### 局部重绘

底图固定为图 1，蒙版绑定底图引用；参考图可选。更换底图后旧蒙版立即失效，必须重新绘制。蒙版输入使用现有 `MaskEditor`，不复制第二套画笔实现。

## 6. 键盘与动态行为

- Enter 在输入框中换行；Ctrl/Cmd + Enter 发送；
- IME composition 期间 Enter 不发送；
- 发送后锁定当前轮发送按钮，但允许编辑下一轮草稿；
- 同一对话存在活动轮次时禁止再次发送；其他对话不受该对话锁影响；
- 尊重 `prefers-reduced-motion`，减少动画时取消 dock 滑入过渡；
- 历史区滚动位置属于本地 UI 状态，不进入文档历史或 session 文档；
- 侧栏展开/收起及模式切换不自动发送、不自动选中最新结果。

## 7. 三档验收断言

每个窗口执行：

- 对话按钮不与属性按钮重叠；
- dock 宽度分别为 360/400/440px；
- 画布 viewport 的 zoom 和 x/y 平移值在切换前后保持一致；
- 画布没有横向滚动条；
- 历史区可独立滚动，底部输入区始终可见；
- Tabs、按钮、输入框和结果操作具备可访问名称与键盘 focus；
- 模式草稿切换、蒙版失效、取消多选和 Escape 焦点恢复均可操作。
