# 输入素材标准化契约

最后核对：2026-08-20

## 目的

用户素材以保留原图为优先：不超过 7 MiB 时原样存储，画布直接加载该原图；超过 7 MiB 后才压缩。API易要求的格式、4096 长边与 1.5MB 限制在 Provider 调用前应用于独立请求副本，不改写已保存素材。

## 服务端硬门禁

1. 只接受通过 MIME、Base64 和文件魔数一致性校验的 PNG、JPEG、WebP、GIF。单个原始请求最多 20MiB。
2. Sharp 解码上限为 40,000,000 像素；超过上限或损坏的图片直接拒绝，不写文件和数据库。
3. 原始文件不超过 7 MiB 时保留字节、格式、像素和元数据，不重编码、不缩放。
4. 原始文件超过 7 MiB 时才应用 EXIF 旋转、sRGB 转换和重编码，并将结果控制在 7 MiB 内。
5. 大文件压缩时长边最多 4096 像素且不放大小图。存在实际透明像素时输出 PNG，否则输出 JPEG。
6. JPEG 从质量 92 开始，在质量 80-92 内收敛；仍超过 7 MiB 时按比例缩小尺寸。透明 PNG 通过无损压缩和缩小尺寸收敛。
7. 标准化完成后以独占创建、写入、fsync 的方式原子落盘，再在同一业务步骤写入文件元数据。数据库失败时必须删除已落盘文件。
8. `POST /api/files` 只有在全部步骤成功后返回 `normalized: true`、`mimeType`、`width`、`height` 和 `byteLength`。前端只有验证该响应后才能把 URL 写入图片节点并置为 success。
9. 素材库直接接收 data URI 时复用同一标准化入口。已有本地素材引用不重复改写原文件。
10. Provider 调用前再次查询本地文件元数据。生成结果保持原样；用户上传、素材以及旧文件都对请求副本执行 4096 长边、1.5MB、PNG/JPEG 标准化。处理失败必须发生在任何 Provider 请求之前，且不得改写原文件。

## 模型级二次适配

- GPT Image 2 蒙版编辑继续在调用前校验原图与 Alpha PNG 蒙版尺寸完全一致，蒙版小于 4MB。
- Gemini 内联图片只发送 PNG 或 JPEG；必要时在 Provider 内转换。
- FLUX.2 Pro 在调用前将每张输入图适配为至少 64x64、宽高均为 16 的倍数且总像素不超过 4,194,304。该适配只作用于请求副本，不改写素材原文件。

## 验收

- 不超过 7 MiB 的 JPEG、PNG、WebP、GIF 与上传前字节完全一致，画布图片地址不包含 `/thumbnail`。
- 超过 7 MiB 的图片才压缩，落盘结果不超过 7 MiB。
- Provider 请求副本长边不超过 4096 且字节数不超过 1,500,000。
- 有效 Alpha 保留；完全不透明图片不会因容器带 Alpha 而强制输出 PNG。
- 超像素、损坏或无法收敛的图片返回可操作的 400 错误，磁盘与 `files` 表均无残留。
- 未取得 `normalized: true` 时前端节点不进入 success；服务端仍会在 Provider 调用前检查本地文件元数据。
- 用户上传、素材及历史本地文件在 Provider 调用前完成请求副本标准化；失败时 Provider 调用次数为 0。
- FLUX 收到的所有输入宽高均为 16 的倍数且不超过 4MP。
